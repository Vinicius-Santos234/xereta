## 1. Objetivo

Uma ilha pequena no topo da tela, com um mascote, que mostra ao vivo o que o Claude Code
está fazendo e deixa **aprovar ou negar um pedido de permissão ali mesmo**, sem voltar ao
terminal.

**Uma frase de sucesso:** peço ao Claude Code *"roda os testes e faz o push"*, vou para o
navegador e vejo a ilha passar por "Rodando npm test" até ficar amarela com `git push origin
main`. Clico em **Permitir** sem sair do navegador, e o mascote comemora quando termina.

**E a promessa que não pode quebrar:** o Xereta fechado, travado ou com defeito **nunca**
atrapalha o Claude Code. Sem resposta da ilha, tudo volta a ser como é hoje, com o pedido no
terminal.

## 2. Fora de escopo do MVP

| Vários monitores | Só o monitor principal |
| Esconder durante jogo ou vídeo em tela cheia | Fica para a v2 (está nos riscos) |
| "Sempre permitir isto" (gravar regra de permissão) | Fica para a v2. Antes é preciso confirmar o que o `PermissionRequest` aceita devolver |
| Instalador assinado, publicação, site | Só quando decidir abrir o projeto |
| Sons e easter eggs | Visual primeiro |
| Paridade com o Coucou | Correr atrás de cada recurso dele é uma corrida perdida e tira o foco do que é nosso. O MVP é o núcleo, e depois entram os diferenciais |

## 3. Decisões

| # | Decisão | Escolha | Motivo |
|---|---|---|---|
| D1 | Stack | **Tauri 2** + **JavaScript puro** na interface, sem TypeScript nem framework | Decidido em 02/10: leve para um app que fica aberto o dia todo, com sistema de permissões explícitas e bom para um possível open source. A interface é pequena demais para justificar React |
| D2 | Divisão Rust / JS | **Núcleo fino:** o Rust só recebe HTTP, repassa à página e devolve a decisão. Toda regra de negócio fica em JS | O Rust é escrito uma vez e quase não muda. Adicionar uma fonte nova é só JS. O Rust do projeto também é o seu primeiro Rust: pequeno e completo. *(03/10: liberado por você o Rust de plataforma antes da E2, o que o JS não alcança: recorte da janela e instância única. Regra de negócio continua em JS.)* |
| D3 | Como o Claude Code avisa | Hooks do tipo **`http`**, direto para o app, sem script no meio | Nenhum processo extra a cada evento. Conexão recusada é erro não bloqueante: o Claude Code segue normal (confirmado nos docs em 02/10) |
| D4 | Endereço | Só **`127.0.0.1`**, porta fixa **47321** (configurável). Porta ocupada vira erro visível na ilha | Os hooks no `settings.json` apontam para uma porta fixa. Trocar de porta sozinho quebraria tudo em silêncio |
| D5 | Autenticação | Token aleatório gerado na instalação, enviado como `Authorization: Bearer` e gravado **literal** no `settings.json` | Qualquer programa da máquina consegue falar com `127.0.0.1`. Sem token, outro processo aprovaria um `git push` no seu lugar. O token é literal, e não variável de ambiente, porque variável nova não chega a um processo já aberto (lição de 02/10) |
| D6 | Sem decisão | Resposta vazia, e o Claude Code cai no fluxo normal do terminal. **Nunca permitir por timeout, nunca negar em silêncio** | O pior defeito possível deste app é aprovar algo que você não viu. O segundo pior é negar sem você saber |
| D7 | Espera na ilha | Pedido aberto por até **45 s** (configurável); o `timeout` do hook é de **60 s** | A folga garante que a ilha responda vazio antes de o Claude Code cortar. O valor é revisto depois da V1 |
| D8 | Eventos de status | Resposta imediata, com `timeout` do hook de **2 s** | Status não pode deixar o Claude Code mais lento. Se a ilha travar, o atraso máximo é de 2 s, e só nesse caso |
| D9 | Privacidade | Nada do conteúdo das ferramentas (`tool_input`) vai para disco. O log guarda só a hora, a fonte e o tipo do evento | `tool_input` pode trazer segredo: um `.env` sendo editado, um comando com token |
| D10 | Contrato entre fontes e ilha | **Formato comum de evento** (§4). Cada fonte tem um adaptador em JS que traduz para ele | É o que deixa Codex, Gemini e Ollama virarem só um arquivo novo |
| D11 | Não atrapalhar cliques | A **janela é recortada na forma da ilha** (pílula ↔ ilha expandida, `SetWindowRgn`) em vez de usar clique transparente | Fora do recorte a janela não existe: ela nunca rouba um clique fora da ilha. No Tauri, ignorar o cursor vale para a janela inteira, sem meio-termo. *(03/10: antes a janela mudava de tamanho; mover e redimensionar a cada hover fazia a pílula pular de lado.)* |
| D12 | Identidade visual | **Visual e mascote próprios.** O Xereta **espia por cima da borda** da tela. Nada de quadradinho branco de olhos grandes (é o Mochi), e o termo "Dynamic Island" não aparece em lugar nenhum (é da Apple) | Mecânica igual não é problema; cara igual é. O que torna o app nosso é o personagem |
| D16 | Feito no Brasil | **PT-BR desde a primeira linha**, com todos os textos num arquivo só (`textos/pt-BR.js`), pronto para o inglês depois. O mascote fala como brasileiro ("Opa!", "Bora?", "Deu ruim") | "Feito no Brasil" só pesa se aparecer no produto. Tradução de app gringo já existe (PR #80 do Coucou). O que não existe é um app que **nasce** brasileiro |
| D17 | Plano, não API | **O Xereta usa o plano do Claude por padrão, nunca a chave de API.** Ele não pede chave para funcionar. Se um dia o Xereta chamar o Claude Code (um resumo, um teste), o processo sobe **sem a `ANTHROPIC_API_KEY` no ambiente**, para usar o login do plano. Chave de API só por escolha explícita de quem usa | Decidido por você em 05/10: a sua chave existe no Windows para outros fins, e quem instalar o Xereta também deve gastar do plano, e não da API, sem perceber |
| D13 | Foco | Expandir a ilha **não rouba o foco** do app em que você está | Senão ela atrapalha justamente quem está digitando em outro lugar |
| D14 | Instalar os hooks | `npm run hooks -- instalar` / `remover`: **mostra o diff antes**, só grava depois de confirmar, faz backup com data, **recusa gravar se o arquivo mudou desde a prévia** e pode rodar várias vezes. **Regra (05/10): o Xereta só grava configuração de outro programa (`settings.json`, `settings.local.json`, arquivos do Codex e do Gemini) por uma ação explícita sua, nunca sozinho** (nem para "consertar" hooks ao abrir). Se os hooks estiverem diferentes, ele avisa e oferece; não grava. Isso vale para todas as specs. Ele anota em `%APPDATA%pp.xereta.ilha\instalacao.json` quais chaves ele mesmo criou, para remover devolver o arquivo exatamente como era | O `settings.json` já tem 4 hooks do vault (SessionStart, PreToolUse, PostToolUse, Stop) que **não podem ser tocados**. A prévia com a recusa foi ideia aprendida no Coucou |
| D15 | Repositório | Git local desde a E0. GitHub e licença são decisão sua, antes de qualquer publicação | Abrir o projeto é uma possibilidade, não um plano com data |

## 4. Arquitetura

```
Claude Code ──POST /fontes/claude-code/…─▶ ┌──────── Rust (núcleo fino) ────────┐
  (hooks http, Bearer token)              │ valida token e tamanho              │
                                          │ status → 200 vazio na hora          │
                                          │ permissão → guarda o pedido aberto  │──evento──▶ JS
                                          │ decisão chega → responde o JSON     │◀─comando── JS
                                          └─────────────────────────────────────┘
JS (interface): adaptadores/claude-code.js → formato comum → estado da ilha → mascote
```

**Rotas** (04/10): o Rust separa status de pedido pelo caminho, sem ler o corpo, para não
precisar saber o que é um `PermissionRequest` (D2). Cada hook aponta para a rota dele.

| Rota | Resposta |
|---|---|
| `POST /fontes/<fonte>/evento` | `200` vazio na hora; o corpo vai para a página |
| `POST /fontes/<fonte>/pedido` | Fica aberta até a página responder; sem resposta em 45 s, `200` vazio |
| Sem token ou token errado | `401` (conferido antes de tudo, em tempo constante) |
| Outro método / outra rota / JSON inválido / corpo > 10 MB | `405` / `404` / `400` / `413` |
| Corpo em pedaços (sem `Content-Length`) / cabeçalho > 16 KB / requisição que não chega inteira em 10 s | `411` / `431` / `408` |
| Mais de 64 conexões / mais de 32 pedidos abertos ao mesmo tempo | a conexão nova fecha / o pedido novo volta vazio na hora |

O token, a porta e a espera ficam em `%APPDATA%\app.xereta.ilha\config.json`, criado na primeira
vez com um token de 32 bytes do gerador do sistema. O instalador da E3 lê o token de lá.

**Formato comum de evento** (o contrato da D10):

```js
{
  fonte: 'claude-code',          // amanhã: 'codex', 'gemini', 'ollama', 'script'
  sessao: '<session_id>',
  projeto: 'korus',              // nome da pasta do cwd
  tipo: 'inicio' | 'pensando' | 'ferramenta' | 'permissao' | 'erro' | 'fim' | 'saida',
  resumo: 'Rodando npm test',    // o que a ilha escreve
  pedidoId: '…'                  // só em 'permissao': liga o clique ao pedido certo
}
```

**Do Claude Code para o formato comum** (hooks instalados na E3):

| Hook | Tipo | O que a ilha mostra |
|---|---|---|
| ~~`SessionStart`~~ | `inicio` | **Não instalado** (05/10): o Claude Code ignora hook `http` no `SessionStart` e no `Setup` ("HTTP hooks are not supported for SessionStart", 2.1.289). A sessão aparece no primeiro `UserPromptSubmit`, que traz o `session_id` e a pasta |
| `UserPromptSubmit` | `pensando` | Mascote pensando |
| `PreToolUse` | `ferramenta` | "Lendo billing.ts", "Editando billing.ts", "Rodando npm test" |
| `PostToolUseFailure` | `erro` | Careta rápida, sem travar |
| `PermissionRequest` | `permissao` | Ilha amarela e expandida, com Permitir, Negar e No terminal |
| `Stop` | `fim` | Mascote feliz |
| `StopFailure` | `erro` | Mascote triste, com o motivo |
| `SessionEnd` | `saida` | Sessão some |

A resposta de permissão segue o formato dos docs:
`{"hookSpecificOutput":{"hookEventName":"PermissionRequest","decision":{"behavior":"allow"}}}`
(ou `"deny"`). "No terminal" e o timeout respondem com corpo vazio.

### E1 — A ilha e o mascote
> **03/10 — E1 concluída.** Todos os critérios abaixo passaram; a memória ficou em **82 MB de
> média em 5 minutos** com a pílula a 15 qps (detalhes nas pendências).
>
> **03/10 — personagem e ilha feitos, falta o seu teste na mão.**
> - **Protótipo** (`design/mascote.html`): frajola em Canvas 2D com molas, volume em camadas
>   (técnica estudada no Mochi; personagem nosso), 6 estados + 8 caras extras com gestos de
>   bigode (luvinhas). Você mandou seguir para a ilha, e isso conta como aprovação.
> - **Motor compartilhado:** `src/mascote/gato.js` (desenho) e `src/textos/pt-BR.js` (textos,
>   D16). O protótipo e o app usam os mesmos arquivos.
> - **Ilha** (`src/index.html`, `ilha.css`, `ilha.js`): tudo em JS pela API do Tauri; o Rust só
>   abre a janela. A janela tem sempre o tamanho exato da ilha: para expandir, ela cresce e
>   depois o CSS anima; para recolher, o CSS anima e depois a janela encolhe. *(Trocado em
>   03/10 pelo recorte, ver as pendências abaixo.)*
> - **Medido por depuração remota do WebView2:** a janela fica centralizada no topo, a 8 px; ela
>   expande para 420×110 em menos de 60 ms e recolhe ~1,2 s depois de o mouse sair. Ela não
>   fica focada (`isFocused = false`).
> - **D13 resolvida com `focusable: false`**, que vira `WS_EX_NOACTIVATE` no Windows: a ilha
>   recebe hover e clique, mas nunca rouba o foco. Isso vale também para os botões da E4.
> - **Memória (release, parada, conjunto de trabalho privado): 98–105 MB.** Com GPU dava
>   118–125 MB e o dobro de CPU; com `--disable-gpu` (`additionalBrowserArgs`) a transparência
>   continua certa, conferida por captura de tela real. CPU parada: ~9% de um núcleo (<0,5% do
>   total). Está no limite da meta: é praticamente o mínimo do WebView2.
> - **V4 (fundo branco piscando):** a janela nasce escondida e só aparece depois do primeiro
>   quadro desenhado.
>
> **03/10 — testado na mão por você, tudo passou:**
> - ✅ D11: clicar bem perto da ilha cai na IDE, não na ilha.
> - ✅ D13: com o mouse dentro da ilha, o texto continua indo para o app que estava aberto.
> - ✅ V4: não pisca branco ao abrir.
> - ✅ Bandeja: os estados de teste trocam e o Sair funciona.
>
> **Pendências da E1 (anotadas em 03/10, antes de fechar a etapa):**
> - [x] Com a ilha recolhida, a cara do gato ainda fica um pouco para fora da pílula.
>   **Corrigido em 03/10:** a cabeça descia até y≈40 numa pílula de 34 px e o queixo era
>   cortado. O gato da pílula agora tem raio 12 e centro (22, 19), com orelhas e queixo dentro
>   dela; o canvas caiu de 56 para 44 px, o que dá mais espaço ao texto.
> - [x] Ao expandir e recolher, a animação dá uma engasgada, e no meio dela pisca o texto da
>   ilha completa (um texto aparece no fundo e some).
>   **Corrigido em 03/10, conferido por gravação a 60 qps:** eram duas causas. (1) A janela
>   mudava de posição e de tamanho em duas chamadas, e por 1–2 quadros a pílula pulava 140 px
>   para o lado; mesmo numa chamada só, o WebView2 mostrava um quadro vazio ao crescer. Agora a
>   janela fica sempre 420×110 e só o **recorte** muda (comando `recortar` no Rust, ~20 linhas

>   descobri que os 98–105 MB eram o vale de uma serra: a 30 qps, o renderer do WebView2 crescia
>   ~1,2 MB/s e só devolvia a memória de tempos em tempos (total de ~80 a ~220 MB). Não era o JS
>   (heap de ~2 MB, limpo o tempo todo): era memória nativa de cada desenho do canvas (gradientes e
>   `Path2D` novos por quadro). Com o desenho parado, 67 MB. **A pílula passou para 15 qps** (a
>   expandida segue o ritmo da tela): **média 82,1 MB, mínimo 73,4, máximo 86,9**, plana, em 30
>   amostras de 10 s na release; CPU 7,5% de um núcleo (0,38% do total). Uma leitura só não serve
>   de medida: pode cair em qualquer ponto da serra.
> - [x] **Revisar tudo com o Codex** (código, spec e protótipo). **Feito em 03/10:** 9 achados,
>   7 corrigidos e conferidos na tela. (1) Mudar a escala do Windows com o app aberto agora
>   refaz posição, recorte e canvas. (2) O hover antes do fim da inicialização é ignorado, e uma
>   falha do recorte deixa a ilha recolhida. (3) Instância única por mutex com nome: abrir de
>   novo não cria outra ilha nem outra bandeja. (4) O recorte grande dura o que dura a animação
>   do CSS (1 ms com "reduzir movimento"), e não mais 220 ms fixos. (5) O `recortar` confere a
>   região criada e a libera se o Windows recusar. (7) A pílula é desenhada antes do `show()`,
>   mesmo a 144 Hz. (8) A pílula não calcula mais as 26 molas de bigodes e mãos, que ela não
>   desenha. (9) "Reduzir movimento" acompanha o Windows ao vivo e para também a varredura do
>   olhar, a olhada do "esperando" e o pulso de cor.
>
> **Deixados para o momento certo (achados da revisão de 03/10):**
> - [x] **E2 — CSP de verdade.** **Feito em 04/10:** `default-src 'self'` com o IPC liberado,
>   e o `core:default` trocado por 16 permissões, só as que o código chama. Antes era `csp: null`. Sem risco enquanto tudo é texto local com
>   `textContent`, mas na E2 entra dado de fora (o que o Claude Code manda). Escrever uma CSP
>   restritiva (`default-src 'self'`, com o IPC do Tauri liberado) e trocar `core:tray:default`
>   e `core:menu:default` pelas permissões que o código usa.
> - [ ] **E4 ou quando a bandeja crescer — menus que acumulam no *reload*.** Cada recarga da
>   página cria menus, itens e a imagem do ícone de novo, e só o `TrayIcon` antigo é fechado.
>   Só acontece no dev. Saída: montar a bandeja no Rust (vive o processo inteiro) ou descartar
>   os recursos antigos um a um.
> - [ ] **Se aparecer clique perdido — recorte grande durante a expansão.** Por 180 ms, o
>   recorte já tem 420×110 enquanto a ilha ainda cresce, e um clique na parte transparente cai
>   na ilha. Com o mouse em cima dela é improvável. Acompanhar a animação quadro a quadro traria
>   o engasgo de volta; se precisar, crescer o recorte em 2–3 degraus.

- **Antes do código, o personagem.** Um protótipo em HTML (`design/mascote.html`) com os 6
  estados lado a lado, aprovado por você. Ele precisa ser reconhecível como **nosso** sem
  legenda, e não pode lembrar o Mochi.
- Janela sem borda, transparente, sempre no topo, sem ícone na barra de tarefas,
  centralizada no alto do monitor principal.
- **Recolhida:** pílula de ~140×34 px com o mascote espiando. **Expandida** ao passar o mouse:
  ~420×110 px, em menos de 200 ms, e recolhe 1 s depois de o mouse sair.
- Com o VS Code maximizado atrás, **todo clique fora da pílula chega ao VS Code** (D11).
- Expandir não tira o foco do app em que você está digitando (D13).
- O mascote tem 6 estados, alternáveis por um menu de teste: parado, pensando, trabalhando,
  esperando você, feliz e erro.
- Ícone na bandeja com **Sair**.
- Com a ilha parada, ela usa **menos de 100 MB de memória** (conjunto de trabalho privado do app e
  dos processos do WebView2, **média de 5 minutos**). O número fica anotado.

### E2 — A ponte em Rust
> **04/10 — E2 concluída.** Todos os critérios passaram, duas vezes: em testes automáticos (22 depois da revisão do Codex)
> (`cargo test`, um ou mais por critério) e com `curl` contra o app rodando, lendo a ilha pela
> depuração remota do WebView2.
> - **Rust:** `ponte.rs` lê o HTTP ele mesmo (sem biblioteca, ver a revisão abaixo), síncrono,
>   uma thread por conexão; `config.rs` lê e cria o `config.json`. O Rust nunca escreve frase para a tela:
>   devolve um código (`porta-ocupada`, `config-invalida`…) e o texto sai do `pt-BR.js` (D16).
> - **Quem liga a ponte é a página** (`ligar_ponte`), depois de já estar ouvindo os avisos:
>   nenhum evento chega antes de ter quem o mostre. Recarregar a página não liga outra.
> - **JS:** `ponte.js` entrega cada aviso ao adaptador da fonte e guarda os pedidos abertos

### E4 — Permissão pela ilha
> **Emenda aprovada em 05/10** (vem do teste na mão da E3 e da V1 respondida):
> - **A espera volta a ser longa (45 s).** A V1 mostrou que o terminal pergunta **junto** com a
>   ilha, e vale quem responder primeiro. Uma espera longa não atrasa quem está no terminal, e dá
>   tempo de responder pela ilha (com 5 s, ninguém alcançava a bandeja a tempo).
> - **A ponte percebe quando o Claude Code desiste do pedido.** Respondido no terminal, o Claude
>   Code cancela o hook e fecha a conexão; hoje a ponte não nota, e a ilha mostra o pedido até o
>   prazo acabar. Enquanto espera a decisão, o Rust vigia a conexão: se o outro lado fechou, avisa a
>   página (`desistiu`), que tira o pedido da tela na hora, com o texto de que foi respondido no
>   terminal. O Rust continua sem saber o que é o Claude Code (D2): é só "a conexão fechou".
> - **"No terminal" traz o terminal para a frente.** A conexão do hook vem do processo do Claude
>   Code; o Windows diz qual processo é dono dela (`GetExtendedTcpTable`). Daí se sobe pelos
>   processos pais até a janela do terminal (cmd, PowerShell, Windows Terminal, VS Code) e ela vem
>   para a frente (`SetForegroundWindow`, permitido porque o clique foi seu). Se não achar a janela,
>   nada acontece além do que já acontece hoje. No Windows Terminal vem a janela, não a aba certa.
>   É Rust de plataforma, como o recorte (D2), e não guarda nada sobre o processo.
